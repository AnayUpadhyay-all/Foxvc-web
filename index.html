The Motivation

Why Another Programming Language?

The specific developer problem FoxVC was built to solve.

The Frustration with Existing Scripting Engines

When you need an embeddable scripting engine for a C/C++ project, your options usually force painful trade-offs:

Lua is lightweight, but it lacks native relational persistence, has 1-based indexing, and requires stitching together third-party C bindings for basic tasks. Python is productive, but dragging a 50MB runtime, dynamic library dependencies, and virtualenvs into an embedded tool is overkill. JavaScript / V8 is blazingly fast, but demands massive memory overhead and complex JIT plumbing.

FoxVC fills this exact gap: a small, deterministic language with an exact 25-keyword lexicon, zero dependency headaches, and built-in SQLite relational queries right in the standard runtime shelf.

Honest Engineering Tradeoffs

  • ✓ Great for: Zero-dependency embedded scripting in C desktop or mobile projects.
  • ✓ Great for: Local desktop utilities that need instant SQLite storage without ORMs.
  • ✓ Great for: 2D game prototypes using the built-in Raylib hardware windowing shelf.
  • ✗ Not for: Distributed web microservices requiring heavy async I/O multiplexing.
  • ✗ Not for: Low-level operating system kernel programming.
FoxVC is designed to do a few jobs exceptionally well with zero configuration.
Core Capabilities

Three Architectural Pillars

What makes the FoxVC runtime practical and distinct.

01

Native SQLite Relational Shelf

Relational persistence is a first-class primitive. Open connections, run parameterized queries, and manage local data using dbOpen, dbExecute, and dbQuery without installing external drivers.

db = dbOpen("app.db") dbExecute(db, "CREATE TABLE users (id TEXT, name TEXT)") dbExecute(db, "INSERT INTO users VALUES (?, ?)", [uuid(), "Anay"]) rows = dbQuery(db, "SELECT * FROM users")
02

14 KB Standalone C Virtual Machine

The entire bytecode runtime (engine/foxvm.c) is pure C89/C99 linking only libc and libm. Features a 1-cycle linear pointer bump arena and tail-call optimization that eliminates recursive stack growth.

# Compiles to a 14 KB standalone ELF binary $ gcc -O2 engine/foxvm.c -lm -o foxvm # Zero external dynamic libraries needed $ ldd foxvm => only libc.so.6, libm.so.6
03

Decoupled Web Model (fweb • fskin • flogic)

FoxVC reimagines full-stack composition: semantic structure is written in .fweb, cascading appearance rules in .fskin, and reactive client state in .flogic.

use "design.fskin" use "app.flogic" app = element "page" apply app PageTheme mount app

Origin Story & Development Timeline

FoxVC was not spun up overnight as a quick GitHub experiment. It began on September 2, 2026 as an intensive offline engineering project.

I wanted an independent language that did not borrow keywords from existing languages, didn't require massive runtime runaways, and could compile into a single standalone C executable. The lexer, AST parser, 8MB linear memory arena, 3-address register bytecode VM, and native Raylib graphics shelf were developed, tested, and iterated across hundreds of automated test benches.

On October 10, 2026, following end-to-end verification and the completion of the client-side WebAssembly bridge, FoxVC was open-sourced on GitHub under the MIT License (`v1.0.0`). Today, FoxVC v2.0 brings tail-call optimization, a Language Server Protocol (LSP) daemon, and cross-platform compilation across Linux, macOS, Windows, and Android Termux.
